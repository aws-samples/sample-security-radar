# UI 信息架构（现行，2026-10-23）

用户原则："每个页面都应该有意义，有思维链条：先看什么、再看什么、最后看什么，能一路下钻到某个事件当前的进展流程；
炫酷重要，但不能是效果堆砌。" ⇒ 本文件定义**阅读顺序与下钻路径**，视觉规范见 `UI-BRIEF-v3.md`，数据契约见
`schemas/site-data.schema.json`。

## 1. 一条主线：态势 → 必须处理 → 事件 → 证据 → 来源

| 层 | 回答的问题 | 页面 | 第一眼看到 | 下钻到 |
|---|---|---|---|---|
| L0 态势 | "现在整体怎么样？" | 首页顶部 / 大屏 `#/wall` | `headline` 一句话 + 漏斗（采集→事件→证实→P0）+ 源健康 | L1 / 直接 L2 |
| L1 必须处理 | "我现在该看哪几件？" | 首页 NOW 区 | `now`（≤3 张卡，带理由标签与计时） | L2 |
| L1' 全量监控 | "还有哪些在发生？" | 首页事件流、漏洞视图、Web3 视图 | 按生命周期分组（升级中 / 活跃 / 冷却 / 定稿），可筛选 | L2 |
| L2 事件 | "这件事是什么、多确定、到哪一步了、我该做什么？" | `#/events/:id`（`#/event/:id` 重定向） | **判定区**（P/V/利用状态 + 一句话结论 BLUF + 环境 BLUF 一行）→ **进展流程** → 在你的环境中 → 分析卡 → 证据 | L2' / L3 |
| L2' 在你的环境中 | "打到我们没有？修了吗？" | `#/events/:id?section=env` | BLUF 命中 a/c → 目标位置 → 动作（Security Agent / Continuum 两泳道）→ findings（规则命中优先）→ 补丁 diff | 补丁原文 / 控制台 |
| L3 证据 | "这个结论凭什么？" | 详情页证据区（展开） | 按独立来源分组的时间线，转载折叠 | L4 / 原文 |
| L4 来源与系统 | "数据源可信吗、系统在正常工作吗？" | `#/sources` | 源健康、漏斗明细、降级原因 | 回 L0 |
| L4' Continuum 融入 | "和 AWS 融合到什么程度？还差什么？" | `#/continuum` | AWS Continuum 融入度环（仅 Continuum 一列的 live / 可计入，`utils/continuum.heroView`；Radar、Security Agent 在环下单列，不进该数）+ Continuum "到 100% 还差"清单 → 能力链路（Radar → Security Agent → Continuum）→ 看护的代码 → 最近触发的环境检查 → 资源 | L2'（`?section=env`） |

规则：
- **每页只有一个主角**（L0 = headline+漏斗，L1 = NOW 卡，L2 = 判定区，L3 = 时间线）。
- **每个可点击对象都通向下一层**，并在悬停时预告"点击查看 …"；每页顶部有面包屑（态势 › 必须处理 › 事件 › 证据），可逐级返回。
- **返回上一层时保留上下文**（筛选、滚动位置、选中项）。
- 大屏与首页是同一条主线的两种密度：大屏点任一对象 = 打开 L2 的侧边抽屉，不离开大屏。

## 2. L2 事件详情：自上而下的阅读顺序（硬约束）

1. **判定区**（一屏内可见）：标题 · P 级 · V 级 · 利用状态 · 生命周期词 · `BLUF`（grounded 才显示，否则显示"结论未生成/未通过校验"及原因）· 计时（首见 X 前 / 证实用时）· 环境 BLUF 一行（可点 ⇒ 第 3 项）。
   证实用时口径（唯一）：`progress.corroborated.at − progress.first_report.at`（T1 首报即证实 = 0），不是 `last_updated − first_seen`。
2. **进展流程**（`progress`，代码计算）：横向 stepper，固定 7 个阶段，每阶段显示时间或"未到达"：
   `首报 → 第二独立来源 → 证实(V2) → 官方确认(V3) → 在野利用 → 分析完成 → 定稿(V4)`；
   另起一行"系统处理步骤"（`pipeline_steps`）：采集 ✓ · 聚类 ✓(N 源) · 判定 ✓ · 分析 ok/partial/pending/failed · 影响匹配（未配置，未检查）· 推送（未接入/已推送）。
3. **在你的环境中**（`response`，AWS Security Agent + AWS Continuum）：`undefined`=未接入 / `null`=未触发（写明原因）/ `not_eligible` / 检查中（动作时间线）/ 完成（目标判定 + 代码位置 → findings → 补丁 diff）。判定唯一来源 `utils/response.ts`：response > `event.impact` > `impact_match` 步骤，覆盖时留小字。
4. **为什么是这个等级**：`level_reason` + 信源分组计数 + 转载数。
5. **分析卡**（`analysis`）：What / 影响面 / 利用状态（含来源分歧）/ 处置建议 / 未知项；每句可点引用跳到 L3 对应证据；`grounded=false` 的句子灰显并标注原因（无引用 / 引用不存在 / 数字未核实）。
6. **关键数据**：CVE（KEV、EPSS 分位）、金额历史（Web3）、链上 tx。
7. **证据时间线**（L3）：按独立来源分组，组内转载折叠为"+N"，每条显示来源层级 T1/T2/T3、时间、信号。
8. **变化记录**（`timeline`）：创建、加入证据、等级/严重度/利用状态/金额变化、合并。

## 3. 首页（L0 + L1 + L1'）

```
[面包屑/状态栏：● LIVE · 14/14 源正常 · 刷新倒计时]
[L0] headline（一句话） ··· 漏斗：采集 3,554 → 去重 712 → 事件 248 → 证实 29 → P0 9
[L1] NOW · 必须处理（≤3 大卡：BLUF/标题 · 理由标签 · 计时 · "查看进展 →"）
[L1'] 全量监控：分组 tab（升级中 | 活跃 | 冷却 | 定稿）+ 领域/等级筛选；紧凑行，每行可下钻
```
空状态：NOW 为空时写"当前无必须处理事件 · 最近检查 hh:mm · 源 a/b 正常"（来自 `headline`，不是空白）。

## 4. 大屏（L0 + L1 的高密度形态）

- 中央：`headline` 大标题 + 3D/2D 雷达；**只有 NOW 的 3 个点带引线标签**，其余点无标签。
- 左：事件流（新事件入场动效 = "有东西变了"）；右：NOW 详情卡（BLUF + 进展 stepper 迷你版）→ Web3 损失 → 漏洞 Top。
- 底：漏斗条 + 事件区块带。
- 任何点击 ⇒ L2 抽屉（`#/wall?event=<id>`，刷新可恢复，Esc / 返回关闭并把焦点还给触发处）；抽屉只放 §2 的头两步
  （判定 BLUF → 在你的环境中 chip + 一句话），底部「打开完整详情 →」进入完整阅读顺序。
- 引线标签用引擎自己的相机投影、按 NOW 排名贪心避让（`utils/labelLayout.ts`），放不下退到边栏，2D/3D 同一套。

## 5. 验收（截图走查）

按主线截 7 张：首页 → 点 NOW 第一张 → 事件详情（判定区+进展流程在首屏）→ 展开证据 → 源健康 → 大屏点击事件打开抽屉 → Continuum 融入页（环 + 还差清单在首屏，最近检查行可点进 L2'）。
每张截图回答本层的问题，且能看到通往下一层的入口。
